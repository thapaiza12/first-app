# Grounded writing validation — 2026-10-16

The new workflow applies to each applicant and each job independently, without cached evidence. It separates applicant originals from job requirements, excludes earlier generated prose, checks literal quotations server-side, verifies every sentence against original applicant sources, retries an unsupported draft once, and withholds unresolved output. Offline keyword matching no longer turns negated experience or job criteria into a past-career claim.

Regression tests cover engineer-to-sales transitions; ungrounded sales, consulting, nursing, and management claims; fabricated quotations; job requirements used as applicant evidence; missing, duplicated, uncertain, or uncited verification; unknown references; previous-AI-text contamination; separate applicant/job inputs; conservative achievement/ability/number checks; and the full Gemini transport with simulated responses. Browser tests cover withholding rejected prose, retaining original text, retrying, and exposing evidence quotes.

Live tests used synthetic documents only. An initial three-call run succeeded but surfaced inferred quality-improvement and personality claims. The policy and verifier were strengthened, verification received a reasoning budget, and deterministic checks for unsupported outcome/ability language were added. A subsequent real run completed evidence extraction, drafting, and verification; verification requested regeneration, and Google returned HTTP 429 on that regeneration. No draft was released. Thus the final stricter live rejection path was exercised, while successful release under the final policy still requires a successful live quota window. No live applicant document was used. These checks do not prove zero semantic error or real-world truth.
